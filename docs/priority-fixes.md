# 优先问题修复方案

本文记录全局侦查中发现的五个问题及后续实施方案。它们仍是已知缺陷，
本次桌面界面中文支持没有实施这些修复。建议按以下顺序独立提交，便于回归。

## 1. Override 导出缺少国家代码

**触发与原因：** 修改 Override 中的玩家信息后执行覆盖，或点击 Reset，
`InnerPlayer.get_data()` 的结果没有 `country`，而 `PlayerWidget.update_player()`
直接读取该字段。异常可能进入顶层异常处理并退出程序。普通玩家的
`get_data()` 从旗帜 QLabel 的文字取值，也无法正确保留国家代码。

**实施：** 在玩家对象上保存独立的国家代码属性，收到数据时赋值，普通与编辑
对象导出时都返回 `country`，允许值为空。国家旗帜函数遇到缺失、空值或无图片
时清空 pixmap，不保留上一位玩家的旗帜；读取时使用可选字段默认值。
Reset 使用当前实时数据，保留国家代码。保持 WebSocket 原有字段格式。

**验收：** 修改姓名、文明、队伍后覆盖，以及 Reset，均无异常；有效国家代码
往返不变；空国家代码能清空旗帜；桌面与 OBS 的玩家数据保持一致。

## 2. 多文明建造顺序渲染异常

**触发与原因：** 校验函数接受 `civilization: ["English", "French"]`，
`BoTab.update_overlay()` 却将列表用于字典键查找，产生
`TypeError: unhashable type: 'list'`。

**实施：** 在校验与渲染边界共用文明规范化函数：字符串转为单元素列表，
非空字符串列表按原顺序保留。空列表、非字符串元素和未知文明返回无效。
标题渲染接口改为接收旗帜路径列表，按文明顺序展示全部旗帜，单文明行为不变。
图片缺失时跳过该图片并记录日志，不退出应用。兼容现有 TXT 与 JSON 格式。

**验收：** 单文明、多文明均显示正常；前后步骤、循环切换与勾选状态正常；
无效文明数据安全回退；缺失图片不会导致退出。

## 3. HTTP 阻塞与轮询中断

**触发与原因：** 请求没有超时，版本检查运行在 GUI 线程；时间解析只接受
`.000Z`。部分解析发生在异常捕获之外，Worker 只发出 error，而轮询没有错误
回调继续调度，因此可能永久停止。

**实施：**

- 所有 HTTP 请求统一设置连接/读取超时 `(5, 10)`，先检查状态码再解码 JSON。
  搜索参数使用 `params` 编码；Session 标明应用名称与版本作为 User-Agent。
- 版本检查移入现有线程池，结果通过 Qt 信号更新按钮；重复检查不重复绑定按钮。
- 共用 ISO 8601 解析函数，支持无小数秒、任意有效小数秒、`Z` 和时区偏移，
  内部使用带时区 UTC 时间；游戏历史与轮询共用该函数。
- 为轮询增加错误回调，HTTP、JSON、结构校验和转换失败均记录日志并保留最后
  有效界面，按现有间隔重试。通过在途标记保证仅一个检查任务。
- 没有玩家 ID 时不请求；换玩家时递增会话代号，忽略旧任务结果；关闭时停止
  后续调度，不允许 error/finished 回调重新启动检查。

**验收：** 模拟超时、HTTP 429/500、坏 JSON、缺失字段及多种时间格式；
GUI 可继续操作，后续有效响应恢复更新。反复换玩家或休眠恢复不会产生并行
轮询；关闭后不会重启任务。历史中一条坏记录不能让所有有效记录消失。

## 4. 对局结束后的历史刷新

**触发与原因：** 主界面等待 `new_rating`，当前检查器却未生成该事件；
仅比较开始时间，无法识别同一场游戏由进行中变为结束。

**实施：** 将检查结果定义为内部事件 `{"type": ..., "data": game}`，
事件类型为 `new_game` 或 `game_updated`。记录 `(game_id, ongoing, 各玩家结果,
各玩家 rating_diff)` 快照；新 ID 返回新对局事件，同 ID 有结果变化返回更新事件。
仅收到结构有效的数据后推进快照；重复响应不返回事件。

新局开始、首次返回已结束对局、对局结束及评分补齐时，请求最近两场历史。
历史按 game_id 合并并替换旧数据，跳过仍在进行中的记录。
结束更新不自动弹出悬浮窗；手动暂停自动覆盖不阻止历史刷新。
若上一场的结束事件未被观察到，下一场开始时的历史请求负责补齐。

保留 `/api/v0/players/:profile_id/games/last` 作为轮询入口，官方文档建议使用
这一有缓存的接口检查最新对局，避免反复获取完整历史。
参考：[AoE4World API](https://aoe4world.com/api)。

**验收：** 验证“进行中→结束→评分补齐”、重复响应、启动时已结束、
未观察到结束就开始下一局，以及暂停自动覆盖的情况。每场历史仅一条，结果
与评分更新正确，结束时不弹出悬浮窗。

## 5. 清空快捷键没有注销旧绑定

**触发与原因：** 两处 Delete 分支仅清空控件和配置，没有调用注销方法。

**实施：** 建立按功能管理的注册表，保存 `keyboard.add_hotkey()` 返回的句柄。
Delete 先注销本功能的旧句柄，再清空配置和控件。更换时先注册新绑定，失败
则保留旧绑定；新绑定成功后注销旧句柄，注销失败则撤销新绑定并保留旧状态。
注销使用句柄而非快捷键字符串，避免影响其他功能。休眠恢复清理句柄状态，
仅按非空配置重建绑定；退出时清理注册表。

**验收：** 玩家悬浮窗显示、建造顺序显示、循环、上一步、下一步五种快捷键
分别清空后均不响应；其他绑定继续有效。覆盖重复清空、更换失败、重启、
休眠恢复及多个功能使用相同快捷键的场景。

## 回归实施约定

每项修复添加上述有意义的回归测试；网络与键盘使用模拟对象，GUI 使用离屏
Qt。补充 Windows 上真实快捷键、休眠恢复和 OBS 人工检查。沿用现有依赖，
不同时恢复停用页面、改动配置存储机制或重写 WebSocket 管理器。
